Agent Descriptions

Each agent has a specialized role within the rubysmithing ecosystem. The Sovereign orchestrates all operations.

S
rubysmithing-sovereign
The Sovereign Architect - Orchestrator
Consolidates routing, context resolution, and quality gates into a unified sovereign execution model. Executes the 4-layer model (Survey → Resolve → Dispatch → Audit). Makes all final decisions and ensures zero-hallucination API calls.
R
rubysmithing-researcher
The Epistemic Verifier - Research Agent
Specializes in gem API verification using Context7 MCP. Performs codebase surveys and foreign codebase analysis. Detects conventions, maps dependencies, and verifies external API signatures. Provides verified context blocks for builders to use.
B
rubysmithing-builder
The Pragmatist - Builder Agent
Generates, refactors, and structures Ruby code. Uses BlueprintSearchTool to query the Librarian for known-good patterns. Strictly follows Zeitwerk, frozen_string_literal, and Rubocop conventions. Adapts blueprint patterns to fulfill current tasks.
A
rubysmithing-auditor
The Bureaucrat - Auditor Agent
Performs comprehensive SIFT Protocol audits with 8-section assessments. Acts as Judge in Do-and-Judge loops. Evaluates Builder output against established rubrics and provides PASS/FAIL verdicts with evidence. Identifies convention violations, security issues, and quality gaps.
T
rubysmithing-tester
The Quality Engineer - Tester Agent
Creates and runs integration tests, convention tests, and verification suites. Validates gem installations, database connections, and configuration setups. Works alongside Auditor to ensure comprehensive quality coverage.

Communication Flows

The Sovereign maintains bidirectional communication with all agents, enabling both parallel and sequential execution patterns.

Parallel Dispatch

  • Sovereign → Multiple agents simultaneously
  • Independent sub-tasks
  • Example: Verifying multiple gem APIs

Sequential Dispatch

  • Sovereign → Agent A → Agent B → Agent C
  • Dependent task chains
  • Example: /flow command (researcher → builder → auditor)

Do-and-Judge Loop

  • Sovereign → Builder → Auditor → Sovereign
  • Iterative quality improvement
  • Continues until score passes

Cross-Agent Communication

  • Researcher → Builder (verified signatures)
  • Builder → Auditor (implementation artifacts)
  • Auditor → Builder (remediation feedback)

Agent Interaction Code Example

# Sovereign orchestrates the flow
class SovereignAgent
  def execute(request)
    # Layer 1: Survey
    context = detect_conventions(request.project_path)
    dependencies = map_dependencies(request)

    # Layer 2: Resolve
    verified_signatures = @researcher.verify_gem_apis(dependencies)

    # Layer 3: Dispatch - Parallel
    results = Parallel.map(tasks, with: @builder)

    # Layer 3: Dispatch - Sequential
    context = @researcher.analyze_codebase(request)
    result = @builder.generate(request, context)
    verdict = @auditor.evaluate(result)

    # Layer 4: Audit - Do-and-Judge Loop
    while verdict == :fail
      result = @builder.remediate(result, verdict.issues)
      verdict = @auditor.evaluate(result)
    end

    return { result: result, verdict: verdict }
  end
end
